# 网络管理

网络是其他一切赖以正常运行的底层基础。它只在出故障时才受到关注，其余时间则被期望隐形存在，这正是其设计债务能持续多年的原因。

## 按信任级别分段，并切实执行

扁平网络意味着一台被攻陷的笔记本电脑就能直达财务服务器。分段是现有价值最高的结构性控制措施，也是最常被推迟的。

至少应隔离以下类别：用户设备、服务器、管理接口、访客，以及任何无人管理的设备——打印机、摄像头、楼宇系统、承包商设备。最后一类是最常见的入侵入口，因为它们很少打补丁，也很少有人负责。

分段之间默认拒绝，仅放行特定流量。未经审查就不断累积的规则会变成"加了额外步骤的允许全部"；定期审查规则，删除不再有存在理由的条目。

## 远程访问

当员工和工作负载都离开了网络边界，边界就不再是边界。把网络位置视为信任的弱证据：仅凭身处企业网络，不应自动获得访问任何敏感资源的权限。

优先按应用授权，而非授予整个网络的访问权。远程用户只需要一个内部应用，不需要通往整个内部资产的路径——而传统 VPN 默认就会授予这种路径。

认证与授权策略属于 `security:access-and-identity` 的范畴；本技能负责实现网络路径。

## DNS 与地址规划是承重结构

DNS 故障表现为一切都不正常，这就是为什么在许多事件的前二十分钟里它常被误诊。要冗余运行，从客户端视角而非服务器视角监控解析，并将记录纳入变更管控。

规划地址时留出增长空间并做好文档。私有地址段重叠是那种多年后在收购或站点合并时才浮现的问题，而恰好在那个时刻代价高昂。

## 分层诊断

自底向上排查，每一层验证通过后再进入下一层：物理层、地址层、路由层、名称解析层、应用层。大多数误诊源于从应用层开始，因为故障报告正是从那里来的。

间歇性问题是最难处理的，需要随时间持续采集数据，而不是在有人报障的那一刻做一次测试。在受影响的位置持续抓取；没人在受苦时通过的测试证明不了任何东西。

## 多站点放大的是故障模式，而非工作量

第二个地点不是把网络翻倍；它引入了第一个站点从未有过的一类问题。流量现在要穿越一条你不拥有的链路，而远程站点依赖的每一项服务都变成了"它在哪里"的问题。

要有意识地决定什么集中、什么本地。认证、名称解析和打印是站点链路中断时最受影响的三项——一个因为域控制器在别处而无法登录的站点，在所有意义上都是离线的，而不仅仅是失败的那一项。这三项通常值得做本地存活；其余一切通常值得集中。

**站点链路部分故障比完全中断更常见。** 一条通了但性能退化的线路比断掉的线路更难处理，因为没有任何告警，而一切都变慢。要从两端以及路径上监控链路，而不是信任供应商的门户——那只反映他们对自己设备的视角。

在使用软件定义 WAN 的场景中，它通过在链路之间调度流量使退化情况变得可存活，也使拓扑成为集中配置而非逐站点配置的对象。这是实实在在的收益，也是实实在在的风险集中：控制器变成了"它一挂所有人都挂"的东西，因此要把它当作生产基础设施而非管理工具。

小站点会累积例外情况。一个没有空调的机柜、一台没人打过补丁的交换机、一段被人复用的地址范围。要为定期现场巡检编列预算——远程管理看不到有人私自添加的线缆，而没有常驻 IT 人员的站点恰恰是偏离标准最远的。

## 绝不

- 运行扁平网络并仅依赖主机控制。
- 在应用级访问即可满足时授予整个网络的访问权。
- 将网络位置视为信任的充分证据。
- 从应用层向下诊断。
