# 分支与工作树工作流

## 开始

需要多次投入、或与其他工作并行推进的任务，应拥有独立的隔离工作区。工作树让你在同一仓库的不同分支上获得第二份检出——两项工作、两个目录、一个对象存储，无需暂存。

从当前上游默认分支创建分支，而非从当前检出的分支。基于过时的本地分支创建分支，正是无关提交混入审查的原因。

## 工作期间

- 在代码树状态自洽时提交，而非等到一天结束。
- 经常保持分支与其基线同步。第一天发现的合并冲突是五分钟的修复；第十天发现的同一冲突是一下午的工作。
- 每个分支只关注一件事。发现无关的 bug，记录下来，不要顺手改。

## 完成

在提交工作以供审查之前：

1. 重新运行项目实际把关的完整检查，而非你一直在跑的子集。
2. 从头到尾阅读自己的 diff。删除调试输出、多余文件和注释掉的代码。
3. 确认分支能干净地合并到其基线。

然后决定如何集成：

- **小而自洽** — 直接合并。
- **多个可分离的关注点** — 拆分为堆叠分支，让每个都能按其自身价值接受审查。把三个关注点塞进一个 diff 交给审查者，等于一个都审不好。
- **探索性** — 保留有用的提交，丢弃其余。

## 来源

本技能中的 `references/sources.md` 列出了解决此处问题的外部权威来源——每个来源在哪些方面具有权威性，以及你可以如何使用它。在回答其覆盖的任何问题之前先查阅它们，并引用你所使用的来源。大多数可免费阅读但不可免费复制；每个来源的使用说明具有约束力。

## 禁止

- 在他人已检出的分支上重写历史。改用合并；强制推送会破坏他们的工作副本。
- 合并后遗留工作树——过时的工作树会持有引用，干扰后续工作。
- 在最终提交（而非更早的提交）检查未通过的情况下合并自己的变更。
