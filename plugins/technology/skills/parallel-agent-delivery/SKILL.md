# 并行 agent 交付

并行是工作的属性，不是偏好。派发前先确认。

## 何时安全

三个条件必须同时满足：

1. **写入面互不重叠** —— 任意两个 agent 不碰同一个文件。不是"不太可能冲突"，而是可证明互不重叠。
2. **无顺序依赖** —— 没有任何一个需要另一个的输出才能开始。
3. **可独立验证** —— 每个结果都能单独评判。

任一不满足就串行执行。两个 agent 编辑同一文件，轻则合并冲突，重则静默丢失更新。

## 派发

每个 agent 拿到一份自包含的任务说明：目标、独占操作面、它自己看不到的上下文、期望的答案形态。Agent 之间不共享记忆 —— 你没写进去的，它就不知道。

要求**结构化返回**，每个 agent 返回相同结构，便于对比结果而非重读。

## 只读展开是最简单的情况

搜索、审计、审查没有写入面，可无风险并行。优先且放心在这里使用并行。

## 整合

- 合并任何结果前，先对照任务说明逐一审查。
- 两个结果对同一事实说法不一致时，谁都不权威 —— 自己裁定。
- 某个 agent 没返回有用结果属正常情况，不要盲目重试。

## 禁止

- 步骤实际是串行的，却为了显得更快而拆分。
- 因为"大概不会撞上"就让两个 agent 写同一操作面。
- 合并你没读过的结果。
