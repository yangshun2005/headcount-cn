# 实现规划

## 何时值得写计划

超过约三步、涉及多个重要文件，或任何需移交的工作。
低于此标准，规划的成本高于收益。

## 编写计划

当未参与对话的人能照着执行而无需猜测时，计划才是可执行的。
这意味着每一步都要写明：

- **变更** — 文件或界面，以及变更后应达到的效果。
- **验证** — 证明其生效的命令。"运行测试"不是一步；确切的调用命令才是。
- **检查点** — 下一步开始前是否需人工审查。

安排步骤顺序，使系统在每一步结束时都能正常工作。中途构建失败的计划无法暂停，而每个计划都会被暂停。

预先声明**范围之外**的内容。计划因不断累积而失败的情况，远多于因错误而失败。

## 执行

- 一次一步，按序进行。完成并验证后再开始下一步。
- **在检查点停下。** 检查点的意义在于：跳过它就是错误。
- 当现实与计划矛盾时，停下并修订计划。不要默默绕过——计划是共享状态，过时的计划比没有更糟。
- 在执行过程中*在计划内*跟踪状态，以便中断后能恢复。

## 绝不

- 因为计划看起来显而易见就开始写代码。如果真显而易见，写下来只需一分钟。
- 未运行验证就标记某步完成。
- 执行中途扩大范围。记录下来，完成计划后再决定。
