# 检测与监控

事件响应假设有人已经察觉。大多数响应得当的组织，其实是从客户、供应商或勒索信那里才知道出了事，而从入侵到发现的这段空档，正是几乎所有损失累积的地方。

## 先问事后需要什么，再决定记录什么

从调查会问的问题倒推：谁通过了认证、从哪里来、之后做了什么。这指向一份简短的清单，其重要性远超日志量。

- **身份事件**——认证成功与失败、MFA 变更、权限授予、新建 API 密钥和令牌、向应用授予的授权同意。
- **端点进程活动**——运行了什么、由什么启动、连接了什么。
- **管理操作**，发生在存放数据的平台上，尤其是权限和共享变更。
- **网络出口**流量（如有），以及 DNS——成本低且信息量异常丰富。

**保留期限决定你究竟能否调查。** 入侵通常在进入数月后才被发现，因此只保留三十天的日志回答不了任何有用的问题。分开处理：一个可快速搜索的热窗口，加一个仍可访问的更长冷归档。

## 集中存储，并让副本难以抹除

只存放在产生日志的系统上的日志，就是攻击者控制的日志。日志写入时即从主机发送出去，送到一个凭据与采集来源系统不同的目的地——否则一个被攻陷的管理员账户就能同时终结入侵和入侵的证据。

## 针对行为编写检测，而非针对事件

单个事件几乎从不是事件。区分攻击者的是序列：从新位置认证，接着创建邮箱规则，接着批量下载。

- **从真正适用于你的技术出发。** 覆盖范围是你自身资产的属性，不是厂商规则数量的属性。
- **检测攻击者无法跳过的步骤**——持久化、权限提升、凭据访问和外泄——而非他们可能使用的工具，因为工具会变。
- **低成本可得的高信号检测**：向外部转发或删除的收件箱规则、新建的联合身份或身份提供商信任、被禁用的日志、管理员账户的不可能旅行，以及单一主体的大规模文件访问。

每条检测都需要有文档化的响应。一条触发后没有明确下一步的检测，在第二次出现时就成了噪声。

## 无情调优，因为告警疲劳才是真正的失败模式

一条大多数时候都是误报的告警，会训练人们不读就关掉。团队不再留意，最终真正的那条也以同样方式被关掉。

衡量实际被处置的告警比例。持续低于大约一半就是调优问题，解决办法是收窄或抑制规则，而不是再加一名分析师。少量可信的检测胜过无人相信的广泛覆盖。

## 决定谁在值守，以及何时值守

覆盖时段是一个有成本的明确决策。仅工作时间监控意味着周五傍晚开始的入侵会无人观察地运行两天——这正是攻击选择那个时间的原因。如果无法全天候配备人员，就明说，并选择少量能在任何时段呼叫到人的检测，而不是假装队列有人监控。

外包检测是合理的，但决策不能外包。提供商负责上报；内部仍须有人可被联系到，并有权断开某些东西。

## 测试它是否真会触发

检测覆盖被假设的次数远多于被验证的次数。运行该行为——技术的良性版本——确认告警到达、触达某人，并携带足够采取行动的上下文。从配置页面声称的覆盖不是覆盖。

## 绝不

- 日志保留窗口短于发现入侵通常所需的时间。
- 将日志的唯一副本存放在它所描述的系统上。
- 交付一条没有定义响应的检测。
- 为无人端到端测试过的技术声称覆盖。
